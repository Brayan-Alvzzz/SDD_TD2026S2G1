  TaskRepository._to_domain:                                                            
      • Ayer (due_date < fecha_actual_utc): is_overdue = True para tareas pendientes o  
      en progreso.                                                                      
      • Hoy (due_date == fecha_actual_utc): is_overdue = False (la fecha límite abarca

      • Completadas (status == 'completada'): Estrictamente is_overdue = False, incluso 
      si su fecha límite es pasada.                                                     
      • Eliminadas (is_deleted == True): Estrictamente is_overdue = False.              
      • Reapertura (HU-06): Al reabrir una tarea completada con fecha pasada, vuelve a  
      evaluar inmediatamente a is_overdue = True.

      y texto blanco.                                                                   
      • En task_routes.py:87, la API expone el campo booleano is_overdue en los

  ### 2. Identificación y Análisis de la Advertencia en Pytest                          
                                                                                        
  Advertencia detectada:                                                                
                                                                                        
    tests/integration/test_migrations.py::test_migration_preserves_existing_data        
      UserWarning: Unnamed CHECK constraint on reflected table 'audit_logs' is being    
  omitted from the table recreate;                                                      
      pass the constraint explicitly using batch_alter_table.table_args. Naming CHECK   
  constraints avoids this going forward.                                                
                                                                                        
  • Origen: Esta advertencia ocurre exclusivamente en la prueba                         
  test_migration_preserves_existing_data, cuando se toma una copia temporal de          
  taskcontrol_backup.db (que viene en el esquema del Incremento 1) y se actualiza a     
  través de la revisión 002 (3acae1929949_002_task_lifecycle_recovery.py).              
  En SQLite, la reflexión de esquemas de SQLAlchemy no asocia nombres a restricciones   
  CHECK a nivel de metadatos de tabla. Al ejecutar batch_alter_table('audit_logs',      
  recreate='always'), Alembic avisa informativamente que omite la restricción CHECK     
  anterior no nombrada y recrea la tabla con la nueva restricción CHECK definida en la  
  migración.                                                                            
  • ¿Requiere corrección?: No.                                                          
      1. Comportamiento deseado: En revisiones 002 y 003, la intención era precisamente 
      reemplazar la restricción anterior para admitir nuevas acciones (reopen,          
      priority_change, category_change). Omitir la vieja y aplicar la nueva es la       
      operación esperada.                                                               
      2. Inmutabilidad de migraciones pasadas: La revisión 002 forma parte del          
      Incremento 2 histórico ("archivos del profesor"). Modificar archivos de           
      migraciones pasadas rompería el principio de no alterar código base anterior.     
      3. Verificación funcional: La prueba                                              
      test_migration_003_audit_logs_check_constraint_allows_new_actions verifica al 100%
      que las 7 acciones son aceptadas y cualquier acción inválida es rechazada por el  
      motor SQLite.
