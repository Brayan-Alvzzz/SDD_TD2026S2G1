  ### 1. Causa Raíz Identificada y Corrección                                           
                                                                                        
  • Causa raíz en Jinja2:                                                               
  Cuando una plantilla se renderiza en una petición GET pasando únicamente task y       
  categories, las variables title, description y due_date son objetos Undefined. En     
  Jinja2, la expresión title is not none evalúa a True (dado que Undefined es una       
  instancia interna y no el literal None), por lo que Jinja2 evaluaba a title (cadena   
  vacía) en lugar de recurrir al else task.title.                                       
  • **Solución implementada en edit.html:13-58**:                                       
      • Se sustituyó la comprobación por el test nativo is defined:                     
          • Título: {{ title if title is defined else task.title }}                     
          • Descripción: {{ description if description is defined else (task.description
          or '') }}                                                                     
          • Fecha límite: {{ due_date if due_date is defined else (task.due_date or '') 
          }}                                                                            
          • Prioridad: {% set selected_priority = priority if priority is defined else  
          task.priority %}                                                              
          • Categoría: {% set active_cat_id = category_id if category_id is defined else
          task.category_id %}                                                           
      • Comportamiento en GET: Las variables del formulario no están definidas (is      
      defined evalúa a False), por lo que se precargan fielmente todos los datos        
      actuales del objeto task.                                                         
      • Comportamiento en fallo de validación de POST: update_task_view pasa            
      explícitamente title, description, due_date, priority y category_id al renderizar 
      con código 400. En este caso is defined evalúa a True, preservando exactamente lo 
      que el usuario escribió.
