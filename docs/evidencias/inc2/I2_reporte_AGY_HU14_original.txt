  ### 1. Resumen de la Implementación                                                   
                                                                                        
  1. Entidad de Dominio y Persistencia (T036, T037):                                    
      • Se definió la dataclass de dominio PasswordResetToken (id, user_id, token_hash, 
      expires_at, used, created_at).                                                    
      • Se implementó PasswordResetTokenRepository con métodos create_token,            
      find_active_by_hash, mark_as_used y revoke_all_for_user.                          
      • Se añadió UserRepository.update_password para actualizar de forma segura el hash
      de la contraseña.                                                                 
  2. Servicio de Notificación en Terminal Local (T038):                                 
      • Se creó ConsoleNotificationService en src/infrastructure/notifications.py.      
      • Imprime el enlace de recuperación con el token únicamente en la terminal del    
      servidor (sys.stdout) para facilitar pruebas locales sin pasarela SMTP, sin       
      persistir tokens en disco ni en archivos de logs permanentes, y con advertencia   
      explícita de entorno local.                                                       
  3. Capa de Dominio y Unidad de Trabajo Atómica (T039):                                
      • En UserService:                                                                 
          • request_password_reset(email, base_url): Valida la sintaxis del correo. Si  
          el usuario existe, genera un token criptográfico de 32 bytes (secrets.        
          token_urlsafe(32)), almacena únicamente su hash SHA-256 (token_hash), define  
          caducidad estricta de 30 minutos, revoca de forma preventiva cualquier token  
          anterior no utilizado para ese usuario y despacha la notificación a consola.  
          Si el correo no existe, ejecuta operaciones ficticias para mitigar variaciones
          de tiempo. En ambos casos, no filtra la existencia del usuario.               
          • reset_password(token, new_password, new_password_confirm): Valida           
          coincidencia de contraseñas y longitud mínima de 8 caracteres; valida que el  
          token exista por su hash SHA-256, no esté marcado como used y no haya superado
          los 30 minutos de vida.                                                       
          • Atomicidad transaccional: La actualización del hash de contraseña y el      
          consumo del token (mark_as_used) se ejecutan en la misma transacción (self.   
          _commit()); ante cualquier fallo, ambas operaciones se revierten (self.       
          _rollback()).                                                                 
                                                                                        
  4. Rutas HTTP y Contratos Web/API (T040):                                             
      • Conformes a password-recovery-api.json:                                         
          • GET /forgot-password: Renderiza la vista de solicitud de recuperación.      
          • POST /forgot-password: Retorna status 200 con la respuesta neutra invariable
          "Si la dirección de correo electrónico está registrada en el sistema, se ha   
          enviado un enlace para restablecer la contraseña." tanto para correos         
          registrados como no registrados (mitigación de enumeración de usuarios). El   
          token nunca se expone en la respuesta web ni en la API.                       
          • GET /reset-password/<token>: Valida la vigencia y no consumo del token. Si  
          es inválido o expiró, redirige 302 a /login con mensaje de error; si es válido,
          presenta el formulario de nueva contraseña (status 200).                      
          • POST /reset-password/<token>: Consume el token y actualiza la contraseña de 
          forma atómica. Redirige a /login en interacción web o retorna 200 JSON en API 
          REST. Responde 400 ante discrepancias de contraseña o tokens ya               
          consumidos/expirados.                                                         
                                                                                        
  5. Plantillas Jinja2 e Interfaz (T041):                                               
      • Creada forgot_password.html.                                                    
      • Creada reset_password.html.                                                     
      • Añadido el enlace de recuperación «¿Olvidó su contraseña?» en login.html:24-31.
